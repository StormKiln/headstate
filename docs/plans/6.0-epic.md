# 6.0 — Honesty, stability and the seams that were never joined

Consolidated from a six-theme analysis pass (2026-09-18). 43 proposals surfaced;
this plan takes 24 into 6.0 and defers 19 to 7.0.

## The spine: four verified defects

Each is a case where the app states something untrue. Verified by reading, not inferred.

1. **The diagnostic log breaks its own privacy promise.**
   `SettingsDialog.tsx:363` claims "Counts and timings only — never repository
   names, titles, or tokens." `help/topics.ts:570-573` adds "Error messages from
   GitHub are recorded on the Rust side only after they have been scrubbed."
   Against that: 30 unconditional `log::` sites interpolate repo/branch/path
   (`commands.rs:178` writes `{repo}#{number}` on every PR action, not behind
   `diag!`), and `grep redact|scrub|sanitiz` over the Rust tree returns nothing
   outside tests. A working `SCRUB` table exists at `report.ts:30-40` — TS side
   only. The help text closes with "the point of the log is to send it to
   someone", so a user acts on the promise.

2. **#1044 is still live in two functions.** `board.rs:1115` holds the correct
   pattern with the reasoning in a comment. `fetch.rs:342` reads
   `budget.requests()`/`spent()` for a diagnostic — proving it understands the
   shared state survives the drop — then discards every retrieved count.
   `fetch.rs:495` is barer: `Err(_) => Err(Timeout)`.

3. **#1050 is still live on 29 paths.** `AUTH_ERR` (`commands.rs:35`) rejects
   through the same `Result<T, String>` channel as a timeout, so "we did not ask"
   renders as "GitHub did not answer", with a retry that cannot work.

4. **`git` has no PATH fallback.** `find_gh` (`auth.rs:239`), `find_claude`
   (`auth.rs:209`) and `HEADSTATE_DOCKER` (`docker/cli.rs:50`) all have one;
   `git` has none against 84 bare `Command::new("git")` sites. A GUI-launched
   `.app` does not inherit the shell PATH — documented for `gh` at
   `auth.rs:139-146`. Worse, `branches/scan.rs:50-53` treats a git spawn failure
   as "no patch-ids", rendering every branch as unmerged rather than as an error.

## Decisions taken (2026-09-18)

**A. Execute vs observe — partial.** Terminal launch is in; headless runs and
settings writes defer to 7.0.

Refinement from the user: once a terminal is configured, the existing Claudify /
Resume buttons launch it directly rather than gaining a sibling button. Copy
moves to the row kebab. Unconfigured, today's copy behaviour is unchanged. This
makes the item more MAJOR than first assessed — a button that copies today will
spawn a process — but it is self-gating on a setting that defaults to unset.
The comments at `commands.rs:1969-1979` and the on-screen sentence at
`ClaudeCodePage.tsx:2989-2996` must be revised as part of the work.

**B. Behaviour change — honesty corrections are the spine.** Take filtering +
row selection and persisted scans. Defer virtualization (browser find-in-page
loss needs its own discussion). Drop fs-watching: it conflicts with a documented
decision to poll (`commands.rs:4085` "Polling, not a watcher", `commands.rs:3822`
on FSEvents watchers dying silently on macOS). All other majors go to a 7.0 epic.

**C. Stricter refusals — yes, via the force path.** Occupied, mid-rebase and
dirty-submodule worktrees stop being removable by the plain path, but the
existing force dialog remains and names what it overrides. Not hard blocks.

## Conflicts and sequencing

- Coalescing is a prerequisite for streamed artifact discovery; both were sized
  assuming the other.
- Filtering changes what "remove all safe" destroys, because the bulk button
  already acts on `shown` (`WorktreesPage.tsx:2714`). There is no per-row
  selection today — `selected` at `:989` is the repo picker. Filtering and
  selection must ship together.
- Two agents independently found no `panic::set_hook` in production. Filed once.
- The peer codebase surveyed is a direct functional peer (parallel coding agents,
  one worktree each), not a loose stylistic reference. It lacks in-progress
  rebase detection, stash reading, submodule rollup and merged-branch cleanup —
  the same four gaps. Two independent codebases stopping at the same places
  raises confidence these are non-obvious rather than declined.

## Out of scope for 6.0 → 7.0 epic

Headless Claude runs; permission-rule writes (needs a hash ledger — a permission
rule has no fingerprint, unlike a hook matcher); list virtualization; filesystem
watching; typed error kind across the Tauri boundary (large, touches the mobile
event payload); transcript content search; cross-session token aggregation.
