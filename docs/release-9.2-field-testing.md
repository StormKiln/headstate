# 9.2 owner field testing

This guide collects evidence from the enterprise laptop and **iPhone 17 Pro** after release. A successful export or synthetic test does not establish field reliability or device performance. Keep #1100, #1487, #1542 and #1737 open until their evidence criteria are met. The notification classifier remains **15 seconds**.

Record the installed versions before starting: desktop version and companion TestFlight version/build. The intended matching release is desktop **9.2.0** with companion **9.2.0 (build 44)**. Companion workflow run [37534702863](https://github.com/StormKiln/headstate/actions/runs/37534702863) successfully uploaded the verified IPA, and the `mobile-v9.2.0` GitHub prerelease is published. Automated access could not verify App Store Connect processing or tester availability. Use the live release and [release epic #1736](https://github.com/StormKiln/headstate/issues/1736) for current delivery status, then record what TestFlight actually offers on the iPhone. Also record macOS/iOS version and phone model. Use the matching companion if build 44 is offered; an older bundled frontend cannot exercise the new controls. Do not include account/repository names, addresses, pairing secrets or private transcript text in the written report.

## Enterprise laptop: capture one ordinary session

1. Open **Settings → General**. Enable **“Write a detailed timing log (for diagnosing slowness)”**. This enables the existing general log and the separate measurement journal. If already enabled after an app restart, turn it off and back on locally before the phase: retained files survive, and the successful local preference acknowledgment establishes a new capture boundary for mounted observations.
2. Open **To Review → All repositories** and let at least two ordinary refresh/recovery cycles happen. Note approximate local times and non-identifying counts (for example, approximately236 To Review /130 Ready), the footer text and row freshness labels. Do not repeatedly force refresh to manufacture traffic. Repeat with a normal repository selection if the symptom depends on it.
3. Open a few Ready PRs and return normally. Note whether newly read draft, queue, review or terminal facts change the list, whether an open disclosure stays usable, and whether an ordinary back/open reuses useful content. Only submit an approval or other action you would already be authorized and willing to perform; diagnostics do not justify a write.
4. Revisit a previously viewed **Stats** window. Note cached content, coverage and subsequent ordinary progress; observe over several days if the symptom requires it. Missing coverage is unknown, not zero. No database inspection or extra acquisition is needed for logging.
5. In **Settings → General → Measurement report**, choose **“Save measurement report…”**. Save near the end of each short phase and preserve the original file. Export remains available with capture off. The shown status refreshes on mount, local toggle and export completion; it is not a live poll.
6. Send that separate report with approximate start/end times, version/OS, non-identifying counts, actions taken and expected/observed behavior. **“Show the log” opens the general log, which contains repository and PR identifiers; it is not the closed measurement report.** No raw database, transcript or company screenshot is required. Turn off capture when the investigation is finished.

Startup alone does not establish mounted client linkage. Native/remote preference changes outside the local acknowledged control may leave an old link that the native collector rejects and counts as loss until a new local acknowledgment. Missing mounted records therefore cannot prove that a view was never displayed. Phone capture has its own identity and never adopts a desktop token as local authority.

## iPhone 17 Pro: short separate phases

1. On the iPhone, open TestFlight and record whether companion **9.2.0 (build 44)** is offered. If it is, install it, pair normally and record LAN/other connection category without addresses. If it is not, report that result in [release epic #1736](https://github.com/StormKiln/headstate/issues/1736) and leave the remaining phone steps pending; absence there is a delivery observation, not a successful field test. Enable desktop capture separately for host work. In phone General settings (also available on the unpaired screen), find **This phone** and enable **“Record phone measurements”**. It defaults off independently of desktop capture.
2. Use a designated synthetic session/fixture already prepared for this test. Keep original fixtures and record their non-private fixture labels/size. Do not seed or overwrite real session data merely for diagnosis. Developers can prepare preserved fixtures with `make bench-transcript` and the existing [native harness instructions](../scripts/transcript-native/README.md); those benchmark outputs are not automatically installed as phone sessions.
3. Open newest content. Scrub to start, middle and end, scroll older pages, and choose **Latest**. Scrubbing to EOF must stay detached until Latest is explicitly selected. Try touch and, if convenient, VoiceOver/keyboard. Note loading/error notices and whether the selected content stays in place.
4. In separate short phases, background/foreground the phone and observe a synthetic session that appends new content. Record approximate phase times and usability symptoms. Hidden intervals are censored; the RAF proxy resumes only after a new visible window commit, not merely because a timer eventually fires.
5. Choose **“Share recent measurement report…”** under **This phone** after each phase. Preserve each report and export the desktop report separately. “Preparing phone measurements…” is preparation, not a completed share. A presented share sheet does not prove the destination saved a file (Android reports presentation rather than destination completion). Confirm the destination yourself; canceled sharing is not evidence transfer. **“Retry phone measurement status”** is available after a control/status failure, not a provider-refresh instruction.
6. Turn off the phone switch when finished. Sharing retained data remains available while off. Send separate desktop/phone files; do not subtract their wall or monotonic clocks to invent end-to-end latency.

The phone shares a bounded recent suffix (8MiB including metadata). A validated omitted prefix is explicitly counted and time-qualified. Short phases/export promptly improve coverage, but do not remove quotas, loss, rotation or missing layers. The desktop journal is bounded (normally8×16MiB); retention duration depends on activity, not a guaranteed number of days. Restarts create new epochs; captures and roles remain separate. Coalesced counts are not individual event timestamps. Missing optional values remain unknown.

## Offline inspection and remaining measurements

From a checkout with Python3, run `make analyze-measurements INPUT=/absolute/report.jsonl`. For structured output use `python3 scripts/measurement-report.py /absolute/report.jsonl --json`. The analyzer is offline, accepts only the closed schema and does not print the input path, unexpected values or raw errors. Preserve originals: it never rewrites them. Exit0 means structurally valid without detected qualifications, **not field acceptance**; exit1 means usable but qualified; exit2 means invalid/truncated/unreadable or a parser bound. A partial summary cannot repair missing evidence.

The report separates role/epoch/capture, native read, client wait and RAF scheduling proxy. It exposes absent domains, source coverage, accepted versus rejected receipts, scoped Stats progress, sampled notification provenance and cumulative loss. Ready qualifiers overlap; they are not a partition. Mounted Stats/Ready distributions preserve their recorded scope and closed presentation dimensions using local population/scope ordinals. Missing scope identity is explicitly `unlinked_mixed`: different selected repositories or owner/windows may share that qualified population, never an inferred identity. Client populations are capped at256, with shared scoped-identity and series caps also enforced. Tail percentiles need enough retained samples (nearest-rank p95 at20, p99 at100); only the first256 samples per series are retained, explicitly qualified when exceeded. Per-series distributions and scoped tokens do not establish a complete action→fact→list→render chain through missing evidence. Historical retained epochs have unknown build attribution unless the actual export proves it.

StopFailure samples describe observed hooks and sampled idle boundaries, not true turn IDs or an unbiased population. Missing source timestamps stay missing; negative deltas, duplicates, ambiguous, unpaired, clock-anomalous and censored outcomes remain visible. Eviction counts pending hook/boundary entries, not sessions or dropped journal records. These data support investigation; they do not change the15-second classifier.

For physical first paint, CPU, JS heap, attributed WebContent memory, compositor presentation or frame-rate budgets, optional Safari Web Inspector/Instruments evidence is still needed. Attribute host and WebContent processes separately; host RSS is not renderer memory and double-rAF is not physical paint. Usability feedback can come first without those tools. Historical synthetic native/browser results are qualified in [transcript performance](transcript-performance.md). Hosted Android compile/unit checks and iOS simulator checks establish build/test coverage, not physical iPhone behavior or performance.
