## Global Constraints

- Preserve all synthetic repositories, fixtures and native test-device data.
- No private log content, identifiers, original company paths or telemetry aggregates in committed/public artifacts; use source and synthetic evidence.
- Partial is not nothing; absent is not zero; unknown evidence does not confer fresh readiness or completeness.
- Preserve account/provider/host/list/generation isolation and existing ordered source receipt rules.
- No automatic replay of writes; no bypass of applicable provider retry deadlines; bound all waits and count actual transport attempts.
- Initial shared GitHub limits: four reads total, two background/advisory; Ready advisory eight attempts/30 seconds and ten-second command budget. Any justified adjustment requires recorded evidence and review.
- Shared frontend changes require companion tests; optional wire evidence preserves older successful payloads and schema freshness.
- Product work is one task implementer at a time because client/hooks/model files overlap. Independent review/log analysis may run alongside it. Reuse the available agents rather than exceeding the host cap.
- Use make lint and repository verification/release skills. Do not edit release version placeholders; tags stamp bundles.

## Review Focus

1. A cached Ready row omitted by a partial refresh remains visible with qualification; a new unknown row must not become Ready (Task2).
2. Confirmed approval/changed head cannot be resurrected or hidden by partial inventory and lagging reads (Tasks2/7/9).
3. Cancellation, two windows and slow advisory work must not leak permits, duplicate transport attempts or starve selected detail (Tasks3/4/9).
4. Cooldown/reset boundary and out-of-order response windows must recover once without serving another account's receipts (Tasks3/8).
5. Repeated early activity, unreadable prefixes and provider search ceiling must not falsely converge or permanently starve reachable late rows (Tasks4/5).
