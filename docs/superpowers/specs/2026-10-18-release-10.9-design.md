## Design decisions and constraints

Use the existing React/TypeScript/Tauri/Rust/SQLite architecture and Make targets. No new checkout, personal account, private corpus or provider credential. Synthetic data and failed-run artifacts stay under the existing checkout or explicit temporary evidence paths and are not deleted. Instrumentation is absent from ordinary builds except necessary production correctness fixes. No database authority derived from telemetry. No live provider quota claims from synthetic cost profiles.

Task implementation is sequential where files/interfaces overlap; independent read-only investigation/review may run concurrently. Each task gets failing regression evidence, scoped verification and independent review. New substantiated defects are filed or added to their existing owning issue and linked natively to #1851. Only merged completed fixes close issues. The unresolved native crash must not be reported as fixed solely because release CI passes.

## Builder-check decisions

Application-only memory is not a release requirement: native RSS and Chromium renderer heap remain telemetry-inclusive, with separate recorder/trace measurements and A/B observer-cost evidence. Application-only/browser-process/WebKit heap memory stays explicitly unknown. This avoids unsupported subtraction claims.

The authoritative resource calibration host is this existing macOS arm64 workstation, identified by recorded CPU/OS/architecture and exact browser/toolchain/build mode. Calibrate Chromium on the fixed 150-review mixed workload: five cold and five warm observations, freeze derived limits, then five independent cold and five independent warm validation runs; five alternating A/B pairs measure observer overhead. WebKit has separate capability-labelled functional/churn/mixed validation, with structural/native accounting and no fabricated JS-heap threshold. Startup baselines retain the existing five cold/five warm per engine design. Record source/binary fingerprints as provenance; before/after source revisions may differ explicitly while environment/workload/build class must match. No host-specific latency envelope becomes a GitHub-runner SLA.

Migration rollback means atomic failed-forward-migration rollback and reopen preserving original schema/data; a downgrade feature is outside scope. Do not dual-write legacy state merely to support an unrequested downgrade.
