# Headstate 8.2.2: reliable enterprise review queues

## Purpose and release contract

Epic #1651 contains #1647, #1648, #1649, #1650, #1652, #1653, #1654, #1655. A github.com user on 8.2.1 with hundreds of review requests must be able to browse a stable queue, read disclosures without interruption, and initiate safe foreground actions while bounded background work progresses. Deliver merged fixes, green exact-commit gates and a fresh v8.2.2 GitHub release. The user explicitly authorized implementation, issue updates, merge, tag and publication; further approval is unnecessary. Preserve synthetic data and do not expose private log identifiers.

## Evidence and design

### Inventory observations and traversal (#1649, #1655)

Current bounded scan returns deltas; only one-page success gets Complete coverage. Reconciling each partial delta marks every omitted row retained. A no-work step publishes an empty delta, downgrading healthy rows. Poll delay applies per tiny step; initial head page is redundantly requested. These mechanisms explain permanent warnings independently of provider outages.

Separate delta application from replacement semantics. An observation retains its actual timestamp and qualification until contrary evidence or an explicit freshness policy warrants changing it; an unrelated page is not evidence of failure. Record completed traversal coverage separately from this step's observations. A healthy terminal traversal may establish coverage using its accumulated validated membership, but must not delete prior pages or interpret non-atomic absence as proven removal. Existing confirmation-based removals and ownership/CAS/action-generation guards remain authoritative. A new pass should not immediately erase the last completed coverage; current progress and real failures must remain distinguishable. Never label a tainted, capped, incomplete or unverified scan complete.

No-work/coalesced steps must not fabricate fresh observations or downgrade saved coverage. Failed/no-observation saves must preserve the prior matching-owner SQLite fetched_at timestamp; checkpoint/failure changes are not newly fetched inventory. Actual provider failures remain visible with usable cached rows. Remove duplicate head reads in the first step. Continue eligible traversal at a bounded cadence within existing admission, deadline, attempt and concurrency limits; do not accelerate unrelated full polls or hidden/advisory work. Respect configured refresh cadence for starting new passes, provider cooldown and foreground capacity. Define and verify a finite request bound for healthy and failing sustained scenarios.

### Advisory evidence (#1654)

Current one-minute display expiry cannot cover an eight-per-thirty-second rotation of hundreds of rows. Preserve qualified last-known display evidence under its account/repo/head/base identity while revalidating on demand; keep freshness required by actions separate. Immutable head-scoped facts can be reused, while mutable policy, collaborators and stack membership need their own validity/invalidation. Unknown is not false. Visible/selected work takes priority, hidden work slows or stops, and finite cache bounds plus identity changes prevent leaks/cross-account reuse. Never increase request budgets to mask cache churn or authorize destructive actions from retained stack evidence.

### Reading and status presentation (#1650, #1652)

Stable module-scope Markdown component types preserve browser disclosure DOM during refresh. Carry provider comment IDs through the shared schema and use stable identities in ordinary, superseded and review comments; optional defaults keep older payloads readable. Legacy collisions have explicitly limited fallback behavior, not fake durable identity. Scope detail rendering to PR/account boundaries. Preserve explicit open and closed choices through pending/success/error/recovery and body edits with unchanged structure. Intentional parent close and leaving the PR may reset descendants as before; new PRs must start with their own defaults.

Use short visible status such as Last known, Pending or Unconfirmed, with accessible full explanation and truthful semantics. Keep title/status layout compact at desktop widths and usable on mobile; shortening text does not fix incorrect classification. Preserve external GitHub navigation and safe action availability.

### Linux packaging and menus (#1647, #1648)

Pinned GTK implementation ignores default predefined Window actions. Use supported Linux ordinary actions wired to minimize, maximize/restore and close with existing close-to-tray semantics. Preserve other platforms. Validate actual GTK entries/actions rather than logical child counts.

Actual 8.2.1 AppImage hides installed host GStreamer plugins and points at a missing bundled plugin directory. Bundle the necessary media framework/plugins/scanner consistently with launcher paths, provide build dependencies, and verify the produced artifact under its own launcher environment. Debian dependency evaluation must use actual dependencies; Ubuntu 24.04 WebKit already brings base plugins transitively. Do not invent a Debian fix or claim the unknown reporter environment was reproduced. Preserve licensing/SBOM obligations of bundled plugins.

## Verification and limits

Use red/green tests at production boundaries and sustained synthetic large-account scenarios, including 275 PRs across 44 synthetic repositories, repeated rotations, churn, cooldown/error/recovery, hidden/visible and selected detail interactions. Assert bounded actual provider attempts and concurrency, stable observations/membership, safe actions, and expanded comments. Mock only external boundaries. Qualify synthetic versus native versus live evidence; do not claim live enterprise performance from fixtures. Add a larger/capped inventory boundary as warranted by scanner limits. Keep GitLab, remote and mobile protocol compatibility.

All required frontend, backend, lint, mobile/remote and cross-platform gates apply. Independent task reviews and final whole-branch review precede protected merge. Validate all check attempts on exact release commit; never rerun or reuse a failed release commit/tag. Source version stays 0.1.0; tag workflow stamps 8.2.2. Publish only verified artifacts, preserve installation caveats, close child issues after merge and epic after release verification.
