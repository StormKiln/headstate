## Identity and boundedness contract

Every process startup gets a random 16-byte `epoch`, supplied by the shell using its existing secure randomness and serialized as fixed hexadecimal; every enable interval gets increasing `capture`. Never correlate opaque IDs across epochs/captures. A process-local interner maps bounded private native keys to monotonically increasing, capture-qualified opaque IDs **in memory only**. Key includes actual owner incarnation/source/window or session incarnation as applicable. Never log key bytes, unkeyed hash, PR number, repository, branch, org, path, title, author, transcript text, session UUID, token, free-form error, URL or request body. No persisted secret/stable pseudonym in this initial slice. Longitudinal reports compare scoped aggregates within each epoch and report restart discontinuities; they cannot prove cross-restart same scope merely because counts match.

Caps (initial declared engineering bounds, not measured performance claims):
- interner 4096 owner/scope/session keys and 1 MiB total key bytes, hard refusal at either capacity until next capture; do not evict/reuse IDs and silently splice histories. Saturation returns None plus counter.
- data queue 1024 records, `try_send` only; separate bounded control lane of 8 requests with single-flight export and immediately atomic admission-disable; never await producer IO. Records serialized <=1024bytes; rejected oversized/invalid record counted.
- coalescing table128 aggregate keys, minute summaries. Max12 routine emitted summaries/minute globally; retain cumulative counters and elapsed interval when deferred, explicitly mark coalescing. Counters never called event timestamps.
- user detail/action and accepted receipt transitions budget 120 records/minute with burst capacity 120; an independent StopFailure budget of 60 records/minute with burst capacity 60; lifecycle/loss metadata is writer-owned and cannot be crowded out by data records; no silent sampling. Repeated state transitions dedup by exact revision/key. If over capacity, emit loss totals through reserved writer metadata, invalidating exact event analysis for that interval. Do not aggregate latency percentiles by averaging percentiles.
- writer retains eight 16 MiB segments (128 MiB history) plus a manifest below 64 KiB. One replacement segment may temporarily raise journal storage to 144 MiB; remove the oldest only after replacement commits. A single export temporary adds at most 129 MiB. Declare the 273 MiB combined payload working-space bound (plus the manifest below 64 KiB and filesystem allocation overhead) separately from retained history. The writer serializes export with rotation (no unlinked pinned segments or copy-all snapshot); data producers continue bounded nonblocking enqueue during export and count overflow. Single writer, symlink/refuse protections, permissions 0600 where supported, app-owned journal directory only.
- 12 routine1KiB records/minute is ~17MiB/day; cap retains roughly7days at that ceiling, less under bursts. This is a sizing estimate, not guaranteed multi-day retention. Actual earliest/latest time and gaps are always exported. Rotation evictions/bytes/loss counters explicit.
- flush every5s or128records; enable/disable/export requests use the bounded control lane; disable closes atomic admission immediately even when either lane is saturated. Each accepted event has a capture-qualified sequence; a flush barrier refers to that sequence and status reads a separately published durable watermark without waiting on writer IO. Crash can lose buffered <=5s under normal operation, but scheduler stalls can exceed it: export only last durable watermark, do not promise crash-loss maximum. Disable prevents new records, drains already accepted queue, closes capture. Writer error latches observable unavailable/lost state and does not retry-spin.

No unbounded task spawn per record, no full read of all rotations into memory, no synchronous disk write in producer locks. Writer owns files and export snapshot selection; producer shutdown/cancellation cannot cancel an accepted flush/export halfway into published output. Bounded flush barrier of 5 seconds: if unmet, report incomplete/unavailable with the last durable watermark; do not promise successful export when the writer or filesystem is unavailable. Status and PR operations never wait for the barrier. Export is single-flight; a second request returns Busy. The accepted snapshot has immutable header/trailer counters and an explicit cutoff sequence.

## Proposed Rust API (producer contract)

```rust
pub struct OpaqueId { capture: u64, id: u64 } // private fields; validated on admission
pub enum Key<'a> { Owner(&'a str), StatsScope { owner: &'a str, scope: &'a str,
    from_day: i32, to_day: i32 }, Session(&'a str) }
pub fn enabled() -> bool;
pub fn intern(key: Key<'_>) -> Option<OpaqueId>; // disabled =>None, no key retention
pub fn next_operation() -> Option<OpaqueId>; // monotonic counter, no retained interner key
pub fn record(event: Event); // enum only; returns immediately, counts refusals
pub fn aggregate(delta: AggregateDelta); // fixed enums/numeric fields only
pub async fn status() -> JournalStatus;
pub async fn export_to(destination: PathBuf) -> Result<ExportReceipt, ExportError>;
```

`intern` is native-only; TS cannot submit private keys. Prefer operation IDs already available in trusted command context over introducing key lookups per row. No one opaque PR identity per inventory row: source/list/status aggregates and single active detail/action operation correlation suffice. Scope/window identity includes actual window bounds to avoid comparing7day/30day counts. Session IDs for StopFailure matching stay native-only. Keep at most 1024 active operation/parent correlations, rejecting overflow with a counter; operation IDs themselves consume no lifetime interner entries. Reject stale capture or retired-owner handles with counted reasons. Retire owner/session correlation when actual ownership retires; epoch/capture-qualified IDs are never reused.

`Event` is serde tagged `kind`, `deny_unknown_fields` on input DTOs, with fixed allowlisted enums and bounded numerics. Producer interfaces:

```rust
Event::QueueReceipt { owner: OpaqueId, list: List, operation: Option<OpaqueId>,
  receipt: Option<OpaqueId>,
  revision: u64, receipt_revision: Option<u64>, phase: Phase, coverage: Coverage,
  rows: u32, receipt_age_ms: Option<u64>, outcome: Acceptance }
Event::Operation { operation: OpaqueId, parent: Option<OpaqueId>, domain: Domain,
  stage: Stage, outcome: Outcome, elapsed_ms: Option<u64>, affected_fields: u16 }
Event::StatsProgress { scope: OpaqueId, days: Option<u16>, covered_days: Option<u16>,
  partial_days: Option<u16>, unknown_days: Option<u16>, retrieved: Option<u32>,
  accumulated: Option<u32>, total: Option<u32>, outcome: StatsOutcome,
  elapsed_ms: Option<u64> }
Event::StopFailureMatch { session: OpaqueId, observed_boundary: Option<u32>,
  observation: StopFailureObservation, delta_ms: Option<i64>,
  observed_lag_ms: Option<i64>, hook_age_ms: Option<u64>, outcome: MatchOutcome }
Event::Transcript { operation: OpaqueId, phase: TranscriptPhase,
  elapsed_ms: Option<u64>, bytes: Option<u32>, rows: Option<u32>,
  resident_rows: Option<u32>, capability: Capability }
```

`AggregateDelta` covers request admitted/refused/canceled/completed (foreground/background separately), active/max concurrency, Stats tick/idle/declined, queue continuation/no-work/candidate counts, transcript idle/hidden/read/growth/eviction. Enums explicitly include unknown, unsupported and unmeasured. Never accept generic string labels or arbitrary JSON maps. Validate finite nonnegative durations and saturating counters; invalid/overflow counters visible. `delta_ms` signed for observed hook-before/after ordering, not absolute duration.

Envelope: schema1, epoch,capture,seq, monotonic_ms, wall_time_ms, role enum desktop/phone, event. Clock regression increments anomaly counter; monotonic durations stay valid. IDs are scoped to role+epoch. No client/server monotonic subtraction without a measured clock mapping.

Export opens existing native save dialog; caller never supplies arbitrary filesystem destination through remote RPC. Desktop export is local only; paired callers cannot trigger desktop save UI or read private diagnostics remotely. All tables explicitly refuse unsupported remote export. Status is local, with no periodic global polling; refresh on opening export panel and after action.

## Export format and analysis

One UTF-8 `.jsonl` file: header with schema/build/platform, first/last durable clocks, epochs/captures, caps and loss/rotation/gap metadata; validated envelope records; trailer with exported record count and completion status. Stream each segment with bounded line reader; cap lines1KiB, reject malformed/unrecognized versions and report omissions. No merge of legacy free-form logs. Serialize streaming export with rotation in the single writer. Freeze the durable cutoff and associated metadata before reading; never silently read replaced paths or include later records in the snapshot. Account queued overflow independently and report the snapshot cutoff honestly. Write temporary sibling, flush, rename only complete export; canceled/failed destination leaves no purported valid report. Header/trailer/count mismatch makes analyzer refuse acceptance claims.

Analysis script emits human-readable aggregate tables for coverage change and gaps, ToReview accepted progress/request/write outcomes, transcript duration distributions by explicitly measured kind, signed StopFailure distribution with unpaired counts. At least count/min/median/max and defined percentile method; no statistical p95 claims from tiny samples. Refuse loss-bearing intervals for exact lineage; permit qualified coarse counts. Across restarts report separate epochs, not stable scope/session continuity. Avoid outputting opaque identity-heavy event dumps by default.

## Producer budget matrix and design review resolutions

- Request admission/completion/refusal, background poll/no-work, idle transcript reads and repeated Stats progress use bounded aggregates, not exact events per row/request/stage.
- User-initiated detail/actions and materially changed accepted queue receipts may use exact operation/transition events within their own 120/minute budget. Exact repeated states are deduplicated within the capture.
- StopFailure timing has its independent 60/minute quota. Record independent observed hook/turn boundaries and explicit unmatched/censored outcomes before applying the 15-second classifier; a queue burst cannot consume this quota.
- Lifecycle, durable watermarks and per-domain loss counters use reserved writer metadata. Lost/coalesced intervals remain visible; missing data never becomes zero.
- Client batches contain at most 32 closed-schema events and 16 KiB encoded input, with per-record validation; they may not supply private keys, arbitrary labels/errors or fabricate native operation ownership. Phone-local and desktop observation epochs remain separate.
- Generation-bearing handles and monotonic operation counters prevent capture aliasing and long-session interner exhaustion. Test disable/re-enable with held operations, queue saturation during opt-out/export, writer stalls, mixed-kind phone retention and sustained enterprise-shaped producer rates.
- Initial records need only support analyses the implementation can interpret. No clock-mapping service, network ingest endpoint or inferred cross-device causality. Report missing domains or mounted linkage explicitly until actual producer support exists.

Implementation cautions from scoped review: the flush watermark tracks successfully accepted records, not assigned-but-refused sequences. A refused sequence must never stall a barrier. Disable closes the old capture before another enable opens a new one, including saturated control queues. Validate every parent/owner handle generation, not only the primary operation. Phone truncation retains whole records and accounts native share copies under existing plugin bounds; its 32 MiB retained-share store is separate from journal/export working space. Loss occurring after a frozen export cutoff is recorded in subsequent metadata, never retroactively mislabeled within that snapshot.

## StopFailure source-provenance correction

Source map: stopfailure-producer-map.md. Production supplies committed hook ingestion and sampled registry idle timestamps, not authoritative upstream turn IDs or a complete transition stream. `observed_boundary` is an optional capture-local ordinal for a sampled boundary, never a true turn number; an unpaired hook has no ordinal. Closed observation variants distinguish ingested_hook, sampled_idle, candidate_pair and retrospective_pair, with explicit unpaired/ambiguous/duplicate/censored/clock_anomaly outcomes. Missing hook timestamps synthesized for legacy storage must remain missing in measurements. Committed-ingestion events follow actual transaction success; capture INSERT OR IGNORE row counts rather than issuing new queries to identify duplicates.

Task 6 may retain at most128 sampled sessions with four pending hooks and four boundaries each for ten monotonic minutes. These bound diagnostic correlation memory, not the production classifier. Expiry/overflow/reset remain counted censoring; repeated unchanged samples are aggregates. Keep source timestamp/private session matching native-only. Candidate comparisons never prove upstream turn membership, even when one candidate exists. Separate sampled/retrospective comparisons from independent ingestion, and never call their distribution unbiased population-wide latency. Observing before the15-second filter removes that selection filter only; it cannot remove sampling or missing/newest-only data. The existing15-second classifier remains unchanged.


## Stats source-provenance correction

Source map: stats-producer-map.md. Current Board/Report/Coverage expose a covered-day union and partial flag, not a partition into complete, partial and unknown days. Use optional `days`/`covered_days`/`partial_days`/`unknown_days`; never infer the missing partition or rescan slices for it. A missing window denominator is absent, not zero days. `retrieved` and elapsed time can be unavailable for observations without those measurements; an actually measured empty result remains zero. Check narrowing from source u64 populations and count overflow rather than presenting a saturated value as exact.

History writes use INSERT OR REPLACE; committed row counts mean upserts, not newly inserted unique PRs. Keep registration, useful partial commit, returned cached data and complete coverage distinct. Cache-only measurement must preserve the existing zeroHTTP/zero-registration/zero-worker-demand contract. Exact native/client scope correlation may use an optional trusted diagnostic handle attached to the existing response while enabled, but never a private scope string, new lookup RPC or a phone-local interpretation of a foreign desktop handle. Unavailable correlation stays explicit.

Task6A receipt linkage: QueueReceipt carries an optional issued receipt handle in addition to operation identity. Mint it only for accepted row publication, bind it to the publishing owner and retain it with those rows/revision. Status-only and rejected updates do not mint or replace it. Validate handle kind, capture, liveness and owner association; receipt identity is not an operation ID. Seed/replay/patch without matching native publication stays explicitly unlinked.
