## Identity and boundedness contract

Every process startup gets random UUID `epoch`; every enable interval gets increasing `capture`. Never correlate opaque IDs across epochs/captures. A process-local interner maps private native keys to monotonically increasing opaque u32 IDs **in memory only**. Key includes actual owner incarnation/source/window or session incarnation as applicable. Never log key bytes, unkeyed hash, PR number, repository, branch, org, path, title, author, transcript text, session UUID, token, free-form error, URL or request body. No persisted secret/stable pseudonym in this initial slice. Longitudinal reports compare scoped aggregates within each epoch and report restart discontinuities; they cannot prove cross-restart same scope merely because counts match.

Caps (initial declared engineering bounds, not measured performance claims):
- interner4096 keys, hard refusal at capacity until next capture; do not evict/reuse IDs and silently splice histories. Saturation returns None plus counter.
- queue1024 records, `try_send` only; never await producer IO. Records serialized <=1024bytes; rejected oversized/invalid record counted.
- coalescing table128 aggregate keys, minute summaries. Max12 routine emitted summaries/minute globally; retain cumulative counters and elapsed interval when deferred, explicitly mark coalescing. Counters never called event timestamps.
- transitions/action/StopFailure evidence budget120 records/minute with burst capacity120; no silent sampling. Repeated state transitions dedup by exact revision/key. If over capacity, emit loss totals through reserved writer metadata, invalidating exact event analysis for that interval. Do not aggregate latency percentiles by averaging percentiles.
- writer eight16MiB segments (128MiB total) plus one small manifest (<64KiB); oldest sealed segment removed only after replacement committed. Export temporary file adds at most128MiB+1MiB while writing. Single writer, symlink/refuse protections, permissions0600 where supported, app-owned directory only.
- 12 routine1KiB records/minute is ~17MiB/day; cap retains roughly7days at that ceiling, less under bursts. This is a sizing estimate, not guaranteed multi-day retention. Actual earliest/latest time and gaps are always exported. Rotation evictions/bytes/loss counters explicit.
- flush every5s or128records; enable/disable/export requests through the same bounded writer. Crash can lose buffered <=5s under normal operation, but scheduler stalls can exceed it: export only last durable watermark, do not promise crash-loss maximum. Disable prevents new records, drains already accepted queue, closes capture. Writer error latches observable unavailable/lost state and does not retry-spin.

No unbounded task spawn per record, no full read of all rotations into memory, no synchronous disk write in producer locks. Writer owns files and export snapshot selection; producer shutdown/cancellation cannot cancel an accepted flush/export halfway into published output. Bounded flush barrier5s: if unmet, export existing durable records with `flushIncomplete=true`, not indefinite UI wait or fake complete export.

## Proposed Rust API (producer contract)

```rust
pub struct OpaqueId(u32); // private field; generated only by interner
pub enum Key<'a> { Owner(&'a str), StatsScope { owner: &'a str, scope: &'a str,
    from_day: i32, to_day: i32 }, Session(&'a str), Operation(u64) }
pub fn enabled() -> bool;
pub fn intern(key: Key<'_>) -> Option<OpaqueId>; // disabled =>None, no key retention
pub fn record(event: Event); // enum only; returns immediately, counts refusals
pub fn aggregate(delta: AggregateDelta); // fixed enums/numeric fields only
pub async fn status() -> JournalStatus;
pub async fn export_to(destination: PathBuf) -> Result<ExportReceipt, ExportError>;
```

`intern` is native-only; TS cannot submit private keys. Prefer operation IDs already available in trusted command context over introducing key lookups per row. No one opaque PR identity per inventory row: source/list/status aggregates and single active detail/action operation correlation suffice. Scope/window identity includes actual window bounds to avoid comparing7day/30day counts. Session IDs for StopFailure matching stay native-only. Retire owner/session correlation when actual ownership retires; epoch/capture-qualified IDs are never reused.

`Event` is serde tagged `kind`, `deny_unknown_fields` on input DTOs, with fixed allowlisted enums and bounded numerics. Producer interfaces:

```rust
Event::QueueReceipt { owner: OpaqueId, list: List, operation: Option<OpaqueId>,
  revision: u64, receipt_revision: Option<u64>, phase: Phase, coverage: Coverage,
  rows: u32, receipt_age_ms: Option<u64>, outcome: Acceptance }
Event::Operation { operation: OpaqueId, parent: Option<OpaqueId>, domain: Domain,
  stage: Stage, outcome: Outcome, elapsed_ms: Option<u64>, affected_fields: u16 }
Event::StatsProgress { scope: OpaqueId, days: u16, complete_days: u16,
  partial_days: u16, unknown_days: u16, retrieved: u32, accumulated: Option<u32>,
  total: Option<u32>, outcome: StatsOutcome, elapsed_ms: u64 }
Event::StopFailureMatch { session: OpaqueId, turn: u32, delta_ms: Option<i64>,
  observed_lag_ms: Option<i64>, hook_age_ms: Option<u64>, outcome: MatchOutcome }
Event::Transcript { operation: OpaqueId, phase: TranscriptPhase,
  elapsed_ms: Option<u64>, bytes: Option<u32>, rows: Option<u32>,
  resident_rows: Option<u32>, capability: Capability }
```

`AggregateDelta` covers request admitted/refused/canceled/completed (foreground/background separately), active/max concurrency, Stats tick/idle/declined, queue continuation/no-work/candidate counts, transcript idle/hidden/read/growth/eviction. Enums explicitly include unknown, unsupported and unmeasured. Never accept generic string labels or arbitrary JSON maps. Validate finite nonnegative durations and saturating counters; invalid/overflow counters visible. `delta_ms` signed for observed hook-before/after ordering, not absolute duration.

Envelope: schema1, epoch,capture,seq, monotonic_ms, wall_time_ms, role enum desktop/phone, event. Clock regression increments anomaly counter; monotonic durations stay valid. IDs are scoped to role+epoch. No client/server monotonic subtraction without a measured clock mapping.

## Native commands and TS API

Foundation exports native `measurement_status`, `measurement_export` plus typed batched `measurement_client_events` if mounted evidence needs it. Export opens existing native save dialog; caller never supplies arbitrary filesystem destination through remote RPC. Local desktop only export initially; paired callers cannot trigger desktop save UI or read private diagnostics remotely. All tables explicitly refuse unsupported remote export. Status is local, with no periodic global polling; refresh on opening export panel and after action.

```ts
interface MeasurementStatus { enabled:boolean; schema:1; epochs:number;
  oldestWallMs:number|null; newestWallMs:number|null; durableRecords:number;
  bytes:number; dropped:number; invalid:number; coalesced:number;
  rotatedOut:number; writerState:'ready'|'disabled'|'unavailable'; }

  oldestWallMs:number|null; newestWallMs:number|null; incomplete:boolean; }
measurementStatus():Promise<MeasurementStatus>;
exportMeasurements():Promise<MeasurementExport>;
recordClientMeasurements(batch:ReadonlyArray<ClientMeasurement>):Promise<void>;
```

Do not return the private destination path in the shareable receipt or journal. UI says “Save measurement report…”, explains counts/timings only, shows covered interval, lost/rotated/incomplete warning and clear retry/error/cancel states. Existing “Show the log” stays distinct and its privacy copy remains truthful. No export automatically sends data anywhere. Export available while logging off for retained captures. Mounted tests must click actual tab/control, await actual save command, and exercise pending/cancel/refusal without manufacturing UI state.

**Phone routing must be explicit before wiring:** default tauri.ts call is remote on paired clients. Do NOT route local phone CPU/render samples or export via that path accidentally. Reuse mobile-local command dispatch conventions and compile shared platform-neutral model/writer through the existing shared-Rust pattern if practical; otherwise foundation desktop-only with a truthful phone-unavailable UI, then complete phone-local sink/export in producer slice before claiming phone logging supported. Phone export uses existing supported native share/save mechanism; it must not send logs to the desktop without an explicit user action. Avoid adding an unvalidated network ingest surface. Phone/main process memory cannot stand in for WebContent memory.

## Export format and analysis

One UTF-8 `.jsonl` file: header with schema/build/platform, first/last durable clocks, epochs/captures, caps and loss/rotation/gap metadata; validated envelope records; trailer with exported record count and completion status. Stream each segment with bounded line reader; cap lines1KiB, reject malformed/unrecognized versions and report omissions. No merge of legacy free-form logs. Freeze segment set under writer coordination; export concurrent with rotation uses retained open handles/copies under cap and never silently reads deleted/replaced paths. Write temporary sibling, flush, rename only complete export; canceled/failed destination leaves no purported valid report. Header/trailer/count mismatch makes analyzer refuse acceptance claims.

Analysis script emits human-readable aggregate tables for coverage change and gaps, ToReview accepted progress/request/write outcomes, transcript duration distributions by explicitly measured kind, signed StopFailure distribution with unpaired counts. At least count/min/median/max and defined percentile method; no statistical p95 claims from tiny samples. Refuse loss-bearing intervals for exact lineage; permit qualified coarse counts. Across restarts report separate epochs, not stable scope/session continuity. Avoid outputting opaque identity-heavy event dumps by default.
