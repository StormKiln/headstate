## Representation and owned publication scope

Schema 49 is the single authoritative format. Metadata remains strict typed JSON;
line/tail/last-block/audit/provenance buffers are raw BLOB columns, and each full
4096-byte block's digest is one 32-byte BLOB row. Migration 49 converts v47 rows
inside the same schema/version transaction and leaves no authoritative legacy
byte arrays/hash strings. Offset-only rows remain offset-only. Runtime history
reads retrieve one digest on demand; the owned hash vector contains only the
current read's dirty delta. Append inserts new digest rows without updating or
deleting old ones; replay atomically replaces its old history.

The reported owned publication bytes sum raw buffer **capacities**, dirty
`Vec<String>` backing plus each digest string capacity, the link vector's
`capacity * size_of<PrLink>` plus its owned string capacities, header string
capacity, and 32 bytes of transient binary-digest codec scratch when needed.
Link entry structs/String handles are included; there is no publication link
tree. Encoding temporarily detaches/restores byte buffers and hashes, so it
makes no raw-buffer or history clone. SQLite bindings borrow them; SQLite's
internal copies are outside this application-owned payload accounting.

This scope excludes fixed `FileRead`/`Checkpoint`/local stack bookkeeping,
parser-owned pending/origin tree nodes and strings, original-checkpoint clones
and record/evidence buffers while reading, SQLite allocations, allocator metadata,
and RSS. The corpus listing, offset map and scheduling vector remain separate
orchestration state that scales with listed-source count; this is not a claim
that the whole refresh uses constant memory. Original checkpoint ownership is dropped **before** metadata encoding
and publication. The parser/read phase still has copies proportional to a
partial record, and historical decoding is not universally memory-bounded.
The full test snapshot reconstruction occurs after timed publication and is not
production staging. After-log `REFERENCE_JSON` is deliberately a reconstructed
legacy-format comparison, not retained production serialization.

Every row includes an additional 32-byte codec scratch. The dense-link fixture
retains duplicate parser outputs and performs idempotent inserts, yielding one
new association; this intentionally exercises link-vector allocation rather
than a favorable deduplicated case.

The measured publication envelope is **24 MiB (25,165,824 bytes)**, giving about
17.46% headroom above the largest measured source, including link backing
storage. Both ignored probes assert this envelope for their measured fixtures;
feature observations flag excess without rejecting or dropping evidence. No
measured source exceeds it, so generation-fenced draft chunks are not introduced
for this workload. This is an empirical publication envelope, not a universal
enforced process-memory cap or permission to discard oversized historical data.
An expanded supported fixture exceeding it requires revisiting chunked staging;
arbitrary decoded historical/parser state remains a distinct memory limit.

The two append cases each perform 5 mutations, retain 16,512 WAL bytes and read
12,288 source bytes (anchor +audit +new block), independent of 1,024 vs8,192
historical digests. Checkpoint encoded deltas are 5,459 and 5,464 bytes, respectively;
metadata integers account for the difference. Separate trigger tests assert
exactly one digest insertion and zero historical digest updates/deletes. No
historical digest vector is loaded or cloned in production.

## Correctness and remaining limits

Each source commits links, header, raw bytes, digest delta and durable next-source
continuation in one immediate transaction, fenced against control and generation
both before writes and before commit. A source committed before later cancel,
reset or DB error remains valid. Pruning is a separate fenced transaction only
for an authoritative listing. Actual read callbacks successfully admit another
writer, proving source body reads occur outside the publication writer lock.
Lexical rotation after the durable last-source path gives each source a turn
across small budgets/reopen, rather than always restarting at newest mtime.

Tests cover cancellation/retry without rereading the completed source, rollback
of the active source, later-source DB failure/reopen, generation/reset races,
partial/pending/provenance/anchor/audit continuity, replacement/middle rewrite,
byte-exact non-UTF8 BLOB evidence, offset-only/checkpoint-only migration, malformed
JSON/digests/offsets, injected migration row and COMMIT failure, and historical
schema preservation. A historical metadata fixture with a 1 MiB pending ID
round-trips without imposing today's 512-byte admission policy on migration:
encoded header 2,097,505 bytes, decoded pending ID 1,048,576 bytes. One observation
was 74,090 us migration and 7,030 us load. Those are explicit unbounded-historical
codec costs, not a guarantee about all legacy data.

The feature-only observer recognizes every new table and continues publishing
mutation callbacks only for successful COMMIT. Inspector absent/unknown states
and existing WAL/RSS semantics are preserved. Mixed-cadence foreground/resource
calibration and whole-branch Linux validation belong to later release tasks.

The committed cancellation RED log replaces the local checkout prefix with
`<checkout>`; test output and numerical evidence are unchanged. The original
local diagnostic remains retained outside the repository.
