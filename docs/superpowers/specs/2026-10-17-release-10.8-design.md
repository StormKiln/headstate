## Behavior

GitLab accepted queue receipts must trigger targeted revalidation of mounted detail/action queries when their source facts change. Same owner and host are required. Replayed, retained, older or wrong-owner evidence must not refresh or overwrite newer state. Complete inventory disappearance may trigger an authoritative detail read; partial omission must not assert closure. Unchanged receipts must cause no request loop. Existing GitHub behavior must be preserved. A failed refresh keeps the prior content, exposes a short truthful stale/error state, and preserves drafts, focus and expansion.

A successful corpus population receipt must make the active nonblank transcript search fresh, with hits and coverage from the same result. Submitting unchanged trimmed search text must explicitly rerun it. Blank searches never run. Failed readback retains the previous result and identifies it as retained; it must not claim nothing was searched when previous hits remain.

The same shared population observer must refresh active session-event and event-profile summaries and mark inactive entries stale. Mounted failure/denial panels must transition from unobserved to observed and update counts after committed handoff data. Failed subsequent reads keep prior evidence with explicit warning. No provider calls, filesystem scans or unconditional polling loops belong in receipt observers.

## Architecture and decisions

Use existing TanStack Query caches and transport events. Preserve the current null corpus receipt wire contract unless evidence proves it inadequate; it represents a successful background pass and supports bounded invalidation of local stored summaries. Consolidate #1871/#1872 into one implementation task because they share observer ownership and hook integration. Event bursts must coalesce; a receipt during a read must produce a subsequent read after settlement rather than repeatedly cancelling work or losing progress. Hidden/inactive consumers are invalidated without reads until active/focused. Teardown disposes listeners and pending work. Because null receipts cannot be replayed, reattaching after a zero-subscriber interval must invalidate affected stored-summary caches and refresh active enabled consumers once; Infinity-fresh caches must not conceal commits made while no listener existed.

Publish GitLab receipt ownership from its actual backend receipt, including empty inventories (#1892). Add an optional frontend owner field for older desktop compatibility. A positive nonempty legacy receipt may prove ownership through every row; an empty ownerless legacy receipt must not authorize queue replacement or absence-triggered revalidation. Wrong-owner envelopes are rejected even if rows are empty or individually look current. Preserve GitHub ownership unchanged.

GitLab acceptance decisions belong beside the queue state reducer, not raw transport arrival. Revalidation is cache-scoped and identity-targeted; it must account for initial live evidence versus a pre-existing detail cache, independent list consumers, auth changes and in-flight requests. Concrete helper boundaries are implementer decisions, with tests required for race behavior.

## Stored search readback (#1893)

Current search and coverage commands perform corpus discovery and mutate discovery state on every read. Remove that scan/write from foreground readback: use the committed index ledger/state/progress already produced by population. Search hits, truncation and coverage must share one SQLite read transaction; standalone coverage must also be snapshot-consistent. Preserve unknown/partial/failed/stopped qualifications and last accepted totals. Coverage describes the last indexed/observed corpus, not a fresh filesystem census. Avoid an uninitialized index claiming a measured empty corpus. A deterministic concurrent writer must not split coverage and hits across versions; a following read must see the new commit. Keep discovery ownership in background population and add a production-call-site guard; the existing observe_discovery helper currently has only foreground production callers, so remove or rehome it intentionally. Completeness must reconcile persisted index state AND population status/total_known: cancelled, failed, timed-out, invalidated, running/deferred or unknown progress cannot license a whole-corpus no-match assertion from old counts. Missing state/progress is conservatively unknown. Distinguish a measured empty completed corpus from never-observed empty state, and preserve accepted totals when a partial discovery is only a lower bound. Retained indexed counts above observed totals must not produce negative remaining counts. Do not persist diagnostic paths solely for this work: use truthful generic stored progress/incomplete qualifications rather than fabricating an unreadable-file count. last_pass_at marks pass start, not proof of successful completion. Snapshot tests synchronize a WAL writer after the first actual reader SELECT, preserve caller-owned transactions, and verify subsequent reads see the new commit.
