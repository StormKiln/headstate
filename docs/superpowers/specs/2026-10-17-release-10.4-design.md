# HeadState 10.4 design

The owner approved a performance/reliability release with an investigation of background jobs, database population and consistent cache-first UI, plus PR Find. Target enterprise workload:50+repositories and150+simultaneous PRs. Ship desktop10.4.0 and companion10.4.0 to GitHub/TestFlight after protected merges.

Preserve existing Rust/Tauri/SQLite and shared React architecture. Use the existing checkout under ~/code; no new worktrees or cleanup of user/synthetic data. Existing account-qualified snapshot CAS, terminal barriers, accepted-fact journals and query coalescing are foundations to retain, not replace. Avoid speculative rewrites or new provider polling. Missing information must remain unknown; partial discovery cannot authorize deletion or complete coverage.

Confirmed work:
- Corpus partial discovery must preserve accepted FTS, PR links and attribution, and carry directory/file uncertainty into coverage.
- FTS replacement and fingerprint advancement must be atomic per file, with durable progress through cancellation/restart.
- Usage import must avoid rereading unchanged oversized files and must perform filesystem work outside SQLite writer transactions. Extend existing resumable indexing (#1221), with bounded admission, cancellation/generation fences and qualified corpus-relative publication.
- GitHub fact replay must avoid unchanged journal writes while preserving version floors.
- Provider admission must retain fresh throttle evidence independent of older primary quota metadata. Shared identity lookup must not turn background admission into a foreground dependency; qualify GitHub cold-client behavior with a regression as well as confirmed GitLab behavior.
- Frontend publications must distinguish semantic changes from duplicate receipts. Stable PR content must avoid unrelated status-only render work. Pending actions belong to PR/account identity; same-PR refresh preserves reading/draft state.
- Find searches loaded PR text, including collapsed content, without provider requests; keyboard and touch entry, navigation, partial-data qualification and focus restoration are required. Use sanitized rendered text, preserve manual disclosures, and do not change list filters.
- Assess Windows updater ZIP use and expand Windows audit coverage with evidence. Prefer removing unused ZIP support for signed EXE delivery if platform feature isolation proves valid; keep macOS/Linux update formats working. No claim of exploitability without proof.

Acceptance uses deterministic regression tests, actual query/write/request counts, synthetic enterprise load and browser reading-state tests. Existing physical-device/enterprise tickets remain field evidence requirements; their absence must not be represented as measured success. Every discovered issue is linked to epic1832; close only implemented/reviewed/merged work. Verify all check attempts before tags and verify delivered artifacts/upload receipts afterward.
