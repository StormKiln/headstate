# HeadState 10.7 SQLite measurements

Synthetic fixtures only, using application-linked SQLite 3.53.2 through Rust tests. Local debug test build; elapsed times are observations, not production promises or CI timing thresholds. Each variant uses a fresh temporary WAL database, auto-checkpoint disabled and WAL truncated after seeding. No personal database or transcript was opened.

## FTS identity (#1852)

Run: `cargo test --manifest-path src-tauri/Cargo.toml --lib store::sqlite_efficiency -- --include-ignored --nocapture`.

Corpus bodies contain repeated synthetic text. The batch replaces 100 sessions inside one immediate transaction; this isolates identity cost and includes mapping writes, but is not a full population-pass benchmark. Production per-session transaction/fence behavior is unchanged.

The mapping removes corpus-sized identity scans. It adds storage and WAL writes (about 6–16% more WAL for these batches); it is a writer-time improvement, not a claim that all write bytes decrease. The regression asserts bounded VM work and use of the session index, not these timings. Existing duplicate and NULL identities are retained by migration; successful authoritative reindex normalizes only that session. Unchanged sessions retain the existing no-reindex behavior.
